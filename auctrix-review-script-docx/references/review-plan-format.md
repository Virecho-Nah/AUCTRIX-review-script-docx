# 审稿计划 JSON 格式

## 示例

```json
{
  "reviewer": "AUCTRIX 剧本审稿",
  "source_sha256": "由 extract_docx.py 生成的正文指纹",
  "comments": [
    {
      "paragraph_id": "p000042",
      "anchor_quote": "维修舰军官：灯塔还在射界里！",
      "priority": "P1",
      "category": "卡点铺垫",
      "diagnosis": "这里目前只是普通射界提醒，还不足以让观众提前意识到灯塔绝对不能受损，因此后续灯塔崩塌的灾难感主要依赖突然揭示。",
      "suggestion": "把提醒改成明确禁忌，并在本集更早处再露出一次维护痕迹；只建立“不能坏”，不要解释塔下真相。"
    }
  ]
}
```

## 字段要求

- `reviewer`：批注作者，默认“AUCTRIX 剧本审稿”。
- `source_sha256`：必须逐字复制自 `document_map.json`，防止把计划写入另一版本。
- `comments`：批注数组，可为空但不得省略。
- `paragraph_id`：必须来自 `document_map.json`，格式为 `p` 加六位数字。
- `anchor_quote`：目标段落中的原文短句。必须能在该段落可见文本中唯一匹配；不要使用省略号代替中间文字。
- `priority`：只允许 `P0`、`P1`、`P2`、`P3`。
- `category`：使用以下统一类别之一：剧情逻辑、跨集因果、单集发动、卡点铺垫、人物动机、人物能动性、人物关系、情绪节奏、信息释放、设定一致性、台词、动作画面、制作可行性、连续性、格式规范、保护项。
- `diagnosis`：说明当前文本的具体机制和后果，不能只换词复述问题。
- `suggestion`：给出动作明确的修改方向，同时说明应保护的功能或悬念。

## 锚点规则

- 同一 `paragraph_id` 默认只能出现一次。多个问题共享位置时合并。
- 集级问题锚定到集标题；场级问题锚定到场标题或首次失效处；台词/动作问题锚定到对应原文段落。
- 若同一句原文在段落中重复，扩大 `anchor_quote` 直到唯一。
- `anchor_quote` 仅用于校验，Word 中的批注范围默认覆盖目标段落，以最大限度保护复杂 run、修订和格式。

## 批注正文生成

脚本自动拼成：

```text
【P1｜卡点铺垫】{diagnosis}
建议：{suggestion}
```

不要在 `diagnosis` 或 `suggestion` 中重复优先级、类别或“建议：”。

## 质量限制

- 每条诊断和建议必须为完整句。
- 不得包含 Markdown 标题、表格或工具路径。
- 不得把整场改写塞进批注。
- 不得使用“可能有点”“感觉不太好”“建议加强”这类无证据措辞。
- “保护项”只用于防止已经有效的设计在修改时被误删，不能用来填充夸奖数量。
